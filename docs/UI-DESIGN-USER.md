# CodePaint Studio 普通用户端 UI 设计

> 应用：`apps/public-web`  
> 面向：未登录访客、普通用户 / 报名者  
> 详细规范：见 [UI 设计总览](./UI-DESIGN.md)

---

# 1. 产品任务

普通用户端的任务不是展示后台数据，而是让合适的人快速理解 CodePaint，并顺利完成报名。

用户在首屏应能回答：

- CodePaint 是什么；
- 目前招募哪些方向；
- 我是否适合报名；
- 需要准备什么材料；
- 从哪里开始报名。

体验关键词：真实、清楚、有创造力、低压力、愿意行动。

---

# 2. 页面与路由

```text
/
├── 招新首页
├── /roles/:role_slug
│   └── 招新方向详情
├── /login
├── /register
├── /apply
├── /apply/success
└── /my-applications
    └── /my-applications/:application_id
```

访问规则：

- `/` 和公开方向详情允许 `guest`；
- `/apply` 需要 `user` 或 `recruiter`；
- `/my-applications` 需要登录；
- 普通用户只能查看和修改自己的报名；
- 招新成员可以访问公开页面，但内部处理统一跳转至 `admin-web`。

# 3. 页面结构

## 3.1 Header

桌面端：

```text
CodePaint Studio                 我们在招募   工作方式   FAQ   [开始报名]
```

登录后右侧显示：

```text
我的报名   用户菜单
```

移动端收起导航，但“开始报名”保持可见。Header 不使用复杂下拉菜单和过多导航项。

## 3.2 首页首屏

首屏采用宽留白、非对称排版和真实项目内容，不能把 Hero 文案放进卡片。

```text
CODEPAINT STUDIO

一起把想法做成真正能运行的作品

我们在寻找愿意动手、愿意协作，也愿意把问题想清楚的新成员。

[开始报名]  [了解工作室]
2026 秋季招新 · 研发 / 设计 / 内容
```

首屏右侧或下方出现真实作品、项目截图、活动照片或工作过程图片。图片应展示实际内容，不使用暗化、强模糊或纯氛围图库。

桌面端首屏底部露出下一段“我们正在招募”的标题；移动端按“品牌名 → 标题 → 说明 → CTA → 下一节标题”排列。

## 3.3 工作室简介

使用短段落和少量事实，不制作公司宣传数据墙。可包含：

- 我们正在做什么；
- 如何从想法走到作品；
- 团队如何协作和反馈；
- 一张真实的项目或工作现场图片。

## 3.4 招新方向

使用编号列表，不使用颜色各异的卡片墙：

```text
01  工程 / Engineering
    做产品、工具和实验，把想法变成可使用的东西。
    [查看方向] [报名这个方向]

02  设计 / Design
    让复杂的想法变得清楚、好用，也有自己的性格。
    [查看方向] [报名这个方向]
```

方向详情必须包含：工作内容、适合的人、期待材料、参与方式、常见问题和报名入口。

## 3.5 报名流程

用三到四步说明预期，不承诺无法保证的时间：

```text
01 提交报名
02 我们阅读材料
03 需要时联系沟通
04 确认后一起开始
```

## 3.6 报名表

建议独立页面，不使用过长弹窗。字段：

```text
姓名 / 昵称                 必填
联系方式                    必填
年级或当前状态              可选
意向方向                    必填
自我介绍                    必填
作品 / GitHub / 其他链接    可选
简历或补充材料              可选
对 CodePaint 的期待         可选
```

交互要求：

- 必填项少而明确；
- 输入错误显示在字段附近；
- 文件上传失败不能清空已填写内容；
- 提交过程中禁用按钮并显示“正在提交报名”；
- 成功后显示报名编号、后续流程和查看报名状态入口；
- 不向普通用户展示内部 AI 分数、内部备注和其他报名者信息。

## 3.7 我的报名

普通用户看到自己的报名记录：

```text
我的报名

2026 秋季招新 · 工程
已提交 / 材料处理中 / 等待联系
提交时间：2026-09-01
[查看详情]
```

只显示适合报名者理解的公开状态，不暴露内部审核结论。允许编辑时提供“补充材料”，状态锁定后说明原因。

# 4. 视觉与组件

## 4.1 视觉层级

- 白色作为主画布；
- 黑色作为标题、正文和主按钮；
- 天蓝色用于方向编号、链接、选中状态和一个主要品牌 CTA；
- 天蓝色面积不超过视口约 10%；
- 内容区使用全宽段落、细线和留白，不套多层卡片；
- 装饰使用细网格、短线、编号和文字高亮，不使用渐变球和漂浮光斑。

## 4.2 Buttons

- 主 CTA：黑底白字，文案为“开始报名”；
- 品牌 CTA：天蓝底深蓝字，同一视口最多一个；
- 次按钮：白底黑字、细边框；
- 外链按钮使用打开新窗口图标；
- 不使用孤立的“了解更多”，改为“查看工程方向”等具体动作。

## 4.3 状态

报名成功、处理中、失败和关闭状态必须同时显示文字和图标或形状，不能只用颜色。

---

# 5. 响应式与验收

断点：`Desktop ≥ 1200px`、`Tablet 768–1199px`、`Mobile < 768px`。

- 移动端 CTA 不被折叠或遮挡；
- 表单字段单列排列，标签和错误信息不重叠；
- 招新方向不产生横向滚动；
- 长文案自然换行，不依赖 viewport 缩放字体；
- 真实作品或项目内容在第一视口或紧邻首屏区域出现；
- 用户能从首页在三次操作内进入报名表；
- 用户提交后能找到自己的报名状态；
- 普通用户无法通过前端路由或 API 读取其他报名者信息。
